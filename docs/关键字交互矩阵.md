# 关键字交互矩阵

> 8 个关键字（safe/only/lock/mask/cage/guard/seal/trace）任意组合的语义契约。
> **自动化锁定**：`internal/checker/interaction_test.go`（TestKeywordInteractions，表驱动）+ `redteam_test.go`。
> 任何组合行为漂移（该拦不拦/该放行报错）都会使测试失败。

## 组合规则（总纲）

1. **关键字声明式叠加**：lock/mask/safe/guard 均为声明式，可对同一变量叠加。
   叠加 = 约束并集，无冲突报错：`mask p; lock p` → p 既不可赋值也不可输出。
2. **纯编译期关键字（safe/mask/lock/guard）彼此独立**：safe 只管危险汇点
   （eval/exec/os.system/subprocess/pickle/SQL），mask 只管输出上下文（print/logging/f-string），
   lock 只管赋值/删除/反射读写，guard 只校验值约束。互不掩蔽、互不清洗。
3. **guard 不构成清洗**：`guard x != ''` 之后 x 的 safe 污点仍有效（值校验 ≠ 类型清洗，
   只有 int()/float()/bool() 显式清洗才消除污点）。
4. **块级关键字（only/cage/trace/seal）不豁免其他关键字**：only 白名单只约束"名字访问"，
   块内 lock 赋值、seal 实例赋值、safe 汇点照样拦截。
5. **escape 全局扫描叠加**：无论任何关键字组合，危险内建（eval/getattr/globals…）与危险
   模块（os/pickle/sys…）的访问都是 E0063-E0066 全局拦截，先于关键字语义。
6. **guard 是约束声明而非定义**：guard 引用的变量必须先定义（E0043/E0039）。
7. **escape 不可豁免**：关键字无法关闭 escape 拦截。`safe x` 声明的 x 流入 `eval(x)` 时
   同时报 E0031（safe 污点入汇点）与 E0063（escape 危险内建）双错——safe 只标记数据源，
   不授予危险调用权限。**only 块内**的危险内建（eval/globals…）由白名单机制拦截：
   编译期 E0045（名字不在 only 名单）或运行时 `_FlyOnly.__getattr__`（`_FLY_SAFE_BUILTINS`
   不含 eval/globals）——双层机制与 escape E0063 殊途同归，均不可放行。

## 交互表（已测组合）

| 组合 | 示例 | 行为 |
|------|------|------|
| guard × lock | `lock X=1` + `guard X>0` + `X=2` | 拦 lock 赋值 |
| guard × safe（条件引用） | `guard len(data)>0` | 放行（读不污染） |
| guard × safe（汇点） | `guard data!=''` + `eval(data)` | 拦（guard 不清洗） |
| guard × mask | `guard len(p)>0` + `print(p)` | 拦 mask 输出 |
| guard × trace | guard 声明 + trace 块 | 放行（共存） |
| guard × seal | guard 类型声明 + seal 类 | 放行（共存） |
| only × seal | only 块内 `admin.role='x'` | 拦 seal 实例赋值 |
| only × lock | only 块内 `X=2` | 拦 lock 赋值 |
| only × safe | only 块内 `eval(data)` | 拦 safe 汇点（白名单不豁免污点） |
| only × 白名单外 | only 块内 `import os` | 拦（E0064） |
| only × 白名单内 | only 块内 `json.dumps(...)` | 放行 |
| safe × mask（独立性） | `safe data` + `print(...)` | 放行（safe 不管输出） |
| mask 输出 | `mask p` + `print(p)` | 拦（E0032） |
| seal × trace | seal 类内 trace 方法 | 放行（共存） |
| seal 属性赋值 | `admin.name='b'` | 拦（静态） |
| lock × mask（叠加） | `mask p; lock p` + `print(p)` | 拦 mask 输出（锁赋值+拦输出） |
| lock × safe（叠加） | `safe data; lock data` + `eval(data)` | 拦 safe 汇点（锁赋值+拦汇点） |
| lock → mask | `lock X='v'; mask X` + `print(X)` | 拦 mask 输出（先 lock 后 mask 合法） |
| guard+safe+mask（三元） | 双污点变量进 eval 与 print | 双拦互不掩蔽 |
| only × seal × trace（三元） | only 内 seal 赋值 + trace 块 | 拦 seal 赋值优先 |
| cage × only × safe（三元） | cage 内 only 块内 eval | 拦 safe 汇点 |

## 边界行为（明确不保证）

- **guard 的值校验不阻止 unsafe 值流入危险汇点**（开发者需在 guard 后显式清洗或断言类型）。
- **lock 不阻止 mask/safe 语义**（声明叠加是特性，防绕过需同时声明）。
- **only 块内允许读取块外名字**（只约束访问名字的"写入/导入"，读取走 escape 全局扫描）。

## 运行时兜底组合

| 组合 | 注入产物 | 兜底 |
|------|----------|------|
| only + seal | `__builtins__` 代理 + `__setattr__` | only 白名单代理 + seal 初始化令牌 |
| trace + cage | 函数包装 + 装饰器 | logging 出入 + SIGALRM/RLIMIT |
| cage + guard | 装饰器 + 断言 | 资源耗尽统一报错 + GuardError |

> 运行时注入互不冲突：各关键字注入到不同层（builtins 代理 / 类方法 / 函数包装 /
> 装饰器 / 断言），无同一注入点竞争。
