# 沙箱运行时性能（2026-08 基准）

> 数据来源：`python3 tools/bench_sandbox.py`（本机 python3.14，min of 7 runs）。
> 测量对象：`__builtins__` 被 `_FlySandbox` 代理后函数/类体内内建名访问的开销。
> 注意：**顶层代码零税**（CPython 模块顶层帧缓存 f_builtins，见 THREAT-MODEL §6.1 E3/E6）。

## 数据表

| 场景 | 纯 Python (ms) | Fly 注入 (ms) | 开销比 |
|------|---------------:|--------------:|-------:|
| fib_recursive（递归 + 无内建调用） | 7.37 | 83.83 | 11.4x |
| arith_loop（纯局部变量算术） | 87.00 | 88.54 | 1.02x |
| str_concat（200k 次 str() 内建调用） | 24.52 | 69.91 | 2.85x |
| list_comp（range/sum 内建） | 8.96 | 33.25 | 3.71x |

## 解读

1. **固定启动税 ~75ms/进程**：注入的 runtime+sandbox prelude（约 300 行：类定义、
   frozenset 名单、`_FlySandbox` 实例化）每次进程启动解析+执行一次。
   `fib_recursive` 的 11.4x 主要来自此项（fib(24) 本身仅 ~7ms）。
2. **边际税仅作用于内建名访问**：纯算术（局部变量，无内建）**≈0 税**（1.02x）。
   `str()`/`range`/`sum` 等高频内建走 `_FlySandbox.__getattr__` 代理，单次开销
   约 200-300ns（2.9-3.7x 场景里内建密集）。
3. **审计日志零常态化开销**：`_fly_sb_audit` 只在违规路径触发，正常代码不写审计。

## 取舍指导

| 场景 | 建议 |
|------|------|
| 长运行/计算密集（>1s，内建不密集） | 开销可接受（启动税摊薄，纯算术无税） |
| 短脚本/高频启动（CLI 工具、CI 步骤） | ~75ms 启动税需评估；可换 `python3 产物.py` 直接跑热启动 |
| 内建极密集（字符串处理、容器转换） | 2.9-3.7x 边际税；将热路径移出函数体到顶层可免除 |
| 需要完全无税 | 顶层代码路径（f_builtins 缓存）已零税；编译期检查是主防线 |

## 审计日志成本（违规路径）

每次违规拦截 = 1 次 stderr 写入（`[fly-sandbox] audit:`），含源码行列号。
高频违规场景（每循环触发）会产生大量 stderr 输出——这是**检测信号**而非正常路径。
