# 新增关键字（语法特性 / 运行时能力）教程

PyFly 是 Python 的安全超集转译器。它内建 8 个安全关键字：`safe`、`mask`、`lock`、`guard`（纯编译期）、`only`、`seal`、`trace`、`cage`（编译期检查 + 运行时注入）。本教程讲解如何给 PyFly **新增一个关键字**（或等价语法特性 / 运行时能力），覆盖 Rust 主编译器（`src/`）与 Go 守护进程（`internal/`）**双端同步**的全部改动点。

> 铁律：**任何关键字改动都必须 Rust + Go 两端一致实现**，且产物需通过 `testdata/golden/*.py` 快照的逐字节互证（`go test` 的 `TestGolden` 与 `cargo test` 的 `build_golden` 对比同一批快照）。一端改、另一端不同步，测试会直接失败。

---

## 0. 先分类：你新增的是哪一类？

| 类别 | 行为 | 现有关键字 | 要不要改 `fly_runtime.py` |
| --- | --- | --- | --- |
| **A. 纯编译期** | checker 只收集信息 / 拦截危险写法，gen 不注入任何运行时代码，产物里**零残留** | `safe` `mask` `lock` `guard` | 否 |
| **B. 编译期 + 运行时注入** | checker 检查语义，gen 注入运行时函数 / 装饰器调用 | `only` `seal` `trace` `cage` | 是（新增运行时函数 / 注入节） |

下文分两类给最小可照做的改动清单，并以 `cage`（B 类典型）为真实范例穿插说明。

---

## 1. 必改文件对照表

| 层 | Rust（主编译器） | Go（checkd / 编译管线） | 作用 |
| --- | --- | --- | --- |
| 词法 `lexer` | `src/lexer/token.rs` | `internal/lexer/token.go` | 注册关键字 token |
| 语法树 `ast` | `src/ast.rs`（`Stmt` 枚举） | `internal/ast/ast.go`（`*Stmt` struct） | 定义节点结构 |
| 解析 `parser` | `src/parser.rs`（分发 + 解析函数） | `internal/parser/parser.go`（分发 + 解析函数） | 把 token 流解析成节点 |
| 语义检查 `checker` | `src/typeinfer.rs` | `internal/checker/runtime.go`（分发）+ `guard.go`/`lock.go`/`only.go`/`taint.go`/`escape.go` | 编译期报错 / 收集信息 |
| 代码生成 `gen` | `src/gen.rs`（分支 + 方法） | `internal/gen/gen.go`（分支 + 方法） | 展开成 Python |
| 运行时 `runtime` | 内嵌 `include_str!("../internal/runtime/fly_runtime.py")` | `go:embed internal/runtime/fly_runtime.py` | **双端共用同一份** |
| 错误码 `errors` | `src/errorinfo.rs`（生成物，勿手改） | `internal/ast/errors.go`（源头） | 报错码登记 |
| 测试 `test` | `tests/build_golden.rs` | `internal/compile/compile_test.go` `TestGolden` | golden 快照互证 |

> 运行时文件 `internal/runtime/fly_runtime.py` 通过 `include_str!`（Rust）和 `go:embed`（Go）被**两端同时引用**，所以新增运行时函数只改这一处即可，双端自动包含。

## 2. 词法：注册关键字 token

**Rust** `src/lexer/token.rs`：

```rust
// 1) TokenType 枚举增加变体（与现有 8 个并列，约 52-59 行）
pub enum TokenType {
    // ...
    Safe, Only, Lock, Mask, Cage, Guard, Seal, Trace,
    YourKw,   // ← 新增
}

// 2) 关键字 → token（from_keyword，约 145-152 行）
"safe" => TokenType::Safe,
// ...
"yourkw" => TokenType::YourKw,   // ← 新增

// 3) token → 字符串（to_string，约 194-201 行）
TokenType::Safe => "safe",
// ...
TokenType::YourKw => "yourkw",
```

**Go** `internal/lexer/token.go`：

```go
var keywords = map[string]TokenType{
    "safe": SAFE, "only": ONLY, "lock": LOCK, "mask": MASK,
    "cage": CAGE, "guard": GUARD, "seal": SEAL, "trace": TRACE,
    "yourkw": YOURKW,   // ← 新增
}
```

> 注意：Go 侧 `TokenType` 是大写常量（如 `YOURKW`），Rust 侧是 PascalCase 变体（如 `YourKw`）。命名风格按各自语言惯例即可，但**语义必须一一对应**。

## 3. 语法树：定义 AST 节点

**Rust** `src/ast.rs`（`Stmt` 枚举内，约 94-160 行）：

```rust
pub enum Stmt {
    // ...
    Cage { pos: Position, has_time: bool, max_time: f64, has_mem: bool, max_memory: i64, body: Vec<Stmt> },
    YourKw { pos: Position, /* 你的字段 */ body: Vec<Stmt> },  // ← 新增
    If { /* ... */ },
}
```

**Go** `internal/ast/ast.go`：

```go
type YourKwStmt struct {
    Pos_  Position
    Body  []Stmt
    // 你的字段
}
func (s *YourKwStmt) Pos() Position { return s.Pos_ }
func (*YourKwStmt) stmtNode()       {}
```

> Go 侧每个 `*Stmt` 必须实现 `Pos()` + `stmtNode()`（空方法即可），否则不满足 `Stmt` 接口，编译不过。

## 4. 解析：从 token 到节点

**Rust** `src/parser.rs`：

```rust
// 1) 在 stmt 分发处（约 198-205 行）加分支
TokenType::YourKw => self.yourkw_stmt(),

// 2) 新增解析函数（参照 cage_stmt 约 561 行）
fn yourkw_stmt(&mut self) -> Option<Stmt> {
    let pos = self.tok.pos;
    self.next(); // 消费 yourkw
    // 解析参数 / 主体（body 用 self.block() 或 suite）
    let body = self.block();
    Some(Stmt::YourKw { pos, body })
}
```

**Go** `internal/parser/parser.go`：

```go
// 1) 分发（约 163-173 行）
case lexer.YOURKW:
    return p.yourkwStmt()

// 2) 解析函数（参照 cageStmt 约 498 行）
func (p *Parser) yourkwStmt() ast.Stmt {
    pos := p.tok.Pos
    p.next()
    body := p.block()
    return &ast.YourKwStmt{Pos_: pos, Body: body}
}
```

> 双端解析逻辑必须产出**结构等价**的 AST（字段一致、body 范围一致），否则后续 checker / gen 行为会分歧，golden 测试必失败。

## 5. 语义检查：checker 拦截或收集

### A 类（纯编译期）

在 Go `internal/checker/runtime.go` 的 `checkStmt` 分发里加分支，把节点交给你的检查逻辑（参照 `MaskStmt` 88 行 / `GuardStmt` 94 行）。检查逻辑通常放在独立文件：`mask`→`taint.go`、`guard`→`guard.go`、`lock`→`lock.go`、`only`→`only.go`。

```go
case *ast.YourKwStmt:
    u.checkYourKw(t)   // 你的检查函数
```

Rust 侧在 `src/typeinfer.rs` 对应遍历节点（参照 851-852、1748、1788 等 `walk` / `check_body` 处的 `match` 分支），如需类型推断就在此处理。

### B 类（编译期 + 注入）

同上在 checker 加分支做语义校验（如 `cage` 校验 `max_time` 范围、参数合法性），但**不修改 AST 生成逻辑**——注入由 gen 负责。

> 任何新增的 `errorf(...)` 报错消息**必须登记错误码**（见第 7 节），否则 `fly error <码>` 查不到、且 `errorcode.rs` 全码抽查单测会失败。

## 6. 代码生成：展开成 Python

### A 类：零运行时残留

gen 里只生成注释或完全透传，**不注入任何 `_fly_*` 函数**。以 `cage` 的「标记」分支为例（实际 cage 是 B 类，这里仅示意纯编译期节点如何静默处理）：

```rust
// src/gen.rs walk 遍历（约 1583/1711/1748/1788 行）只需让 body 继续 walk
Stmt::YourKw { body, .. } => {
    for s in body { walk(sb, s, types); }
}
```

Go 侧 `internal/gen/gen.go` 对应 `case *ast.YourKwStmt:` 同样只 `walk` body。

### B 类：注入运行时调用

**Rust** `src/gen.rs`：

```rust
// 1) walk 分支（约 153 行同类位置）
Stmt::YourKw { body, pos, .. } => {
    self.indent_line();
    self.w(&format!("# fly-yourkw: 开始于 {}:{}\n", pos.line, pos.col));
    for s in body { self.stmt(s); }
}

// 2) 若需装饰器 / 函数调用注入，新增方法（参照 cage_stmt 约 506 行）
fn yourkw_stmt(&mut self, t: &Stmt) {
    let Stmt::YourKw { body, .. } = t else { return };
    for s in body {
        if matches!(s, Stmt::FuncDef { .. }) {
            self.indent_line();
            self.w("@_fly_yourkw()\n");
        }
        self.stmt(s);
    }
}
```

**Go** `internal/gen/gen.go`：

```go
case *ast.YourKwStmt:
    fmt.Fprintf(&sb, "# fly-yourkw: 开始于 %d:%d\n", t.Pos_.Line, t.Pos_.Col)
    for _, s := range t.Body { walk(s) }
```

**运行时函数**（B 类必须）：在 `internal/runtime/fly_runtime.py` 末尾加函数，双端自动包含。参照 `_FlyCage`（如 `class _FlyCage` / 装饰器）：

```python
def _fly_yourkw(func):
    """你的运行时包装：编译期注入，运行时执行。"""
    def wrapper(*args, **kwargs):
        # 你的逻辑（带行列号请走 _fly_loc(line, col) 与 _FLY_SAFE_ERRORS 包装）
        return func(*args, **kwargs)
    return wrapper
```

> 若你的注入节需要在产物里**恒注入**（像 runtime / sandbox 两节），在 Rust `runtime_prelude`（约 261 行）与 Go 侧对应注入点加入开关；如果只是按需装饰函数，走上面的 `cage_stmt` 式方法即可。

## 7. 错误码登记（强制）

新增编译期报错时：

1. **Go 源头** `internal/ast/errors.go`：
   - 在 `format → code` 映射表增加 `"你的报错消息模板": "E00XX"`；
   - 在注册表（`"E00XX": {code, title, help, note, example}`）补该码完整信息（含 `docs/报错清单.md#E00XX` 链接与示例）。错误码从 `E0001` 起连续编号，新增时取当前最大 +1。
2. **重新生成 Rust 侧**：
   ```bash
   go run ./tools/gen_errorinfo
   ```
   它会把 `errors.go` 注册表生成为 `src/errorinfo.rs`（该文件**勿手改**）。
3. `src/errorcode.rs` 有全码抽查单测，新增码后会自动覆盖；`cargo test` 会校验。

> Rust 侧 `src/diagnostic.rs` 的 `error_code` 双份同步表也要保持一致（与 `errorinfo.rs` 同源生成，通常无需手改，但改动报错消息时务必确认）。

## 8. 测试与 golden（发布前必过）

PyFly 用 `testdata/golden/*.fly` 作为「双端互证」快照：Rust `fly build` 与 Go `CheckSource` 各自转译同一 `.fly`，产物都要和手存的 `.py` 快照**逐字节一致**。

### 新增正例 / 反例

1. 写 `testdata/golden/yourkw.fly`（覆盖你的关键字各种形态）。
2. 用 Rust 生成快照（**runtime 改动后必须重生成所有 golden**）：
   ```bash
   cargo build --release
   go build -o target/release/fly-checkd ./cmd/fly-checkd
   for f in testdata/golden/*.fly; do
     b=${f%.fly}
     ./target/release/fly build -o "$b.py" "$f"
   done
   ```
3. 反例（期望编译报错）在 `.fly` 里加注释标记：
   ```python
   yourkw unsafe_thing()   # fly:error E00XX
   ```
   checker 测试会扫描 `# fly:error` 并断言该行确实报对应码。

### 跑全量门禁

```bash
go test ./...                                  # TestGolden 双端互证 + checker 反例
cargo test                                     # build_golden.rs 同批快照 + 错误码抽查
go vet ./...
./target/release/fly fmt --check testdata/golden/   # 新增 .fly 必须 fmt 干净
go test -fuzz FuzzSecurityCheck -fuzztime 30s ./internal/checker/   # 改 parser/checker 后先 fuzz
```

> 改了 parser / checker 后**先跑 fuzz 再提交**（AGENTS.md 硬性要求）。改 fmt / analyze 后跑 `fly fmt --check testdata/golden/` 全仓 .fly 必须干净。

## 9. 发布门禁

按 AGENTS.md，每次更新必须发布 CI + releases：

- 提交后 `git push origin main`（项目用指定的带 token 凭据推送方式）。
- 打 `v*` tag 触发 `.github/workflows/release.yml`：Linux deb/tar.gz、macOS pkg/dmg、Windows zip/installer + GitHub Release 自动发布（产物含 `.sig` 签名）。
- npm 包装 `fly-lang` 会按 tag 版本号发布到 npm。
- VSCode 插件（若有版本变更）走 `vsce publish`。
- 改 `fly_runtime.py` / lexer / gen 后，**务必重生成 golden 快照并本地跑通双端测试**再 push，否则 CI 的 TestGolden 会红。
