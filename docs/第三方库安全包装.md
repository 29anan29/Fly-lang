# 第三方库安全包装（S6 试点）

对应 THREAT-MODEL G1 / B3：第三方库内部是**供应链信任边界**——Fly 不静态审查
`requests` 内部的 socket/ssl 调用（与「sandbox 拦截 import 名」不同，模块内部代码
运行时不再逐行拦截）。缓解方式是**用 Fly 自身收口危险面**，文档化信任声明。

## 信任模型

```
编译产物 ── import requests ──→ requests 内部（socket/ssl/urllib3：供应链信任区）
   │                              ↑ 不静态审查，不逐行拦截
   │── Fly 检查器（编译期）──→ requests 仅经 taint 表放行安全 API
   │── _fly_sb_import（运行时）─→ 白名单 + 模块属性拦截（requests.os 等）
   └── wrapper（本试点）───→ 把网络面收口为 seal 类 + guard 校验
```

三层各守一段：

| 层 | 拦什么 | 放行什么 |
| :--- | :--- | :--- |
| 编译期（checker） | 危险模块 import（E0066）、模块属性（E0064）、汇点（eval/os 等） | requests.get/post 等 taint 表源点 |
| 运行时（sandbox） | import 非白名单（E0063 同名单）、模块属性（`_fly_sb_check_modattr`）、反射链 | 白名单模块导入 |
| wrapper（示例） | URL 协议/路径注入 | 经 guard + safe 校验后的外部数据流向源点 |

**声明**：`import requests` 即接受 requests 及其依赖的供应链信任；Fly 保证的是
用户代码侧的收口（seal/guard/safe）与危险面拦截，不保证第三方模块内部无恶意代码。

## 示例：examples/third_party/safe_http.fly

```python
seal class SafeHttp:
    def __init__(self, base):
        guard base.startswith("https://")   # 协议白名单
        self.base = base
    def get(self, path):
        guard path.isalnum()                # 路径注入防护
        safe path                           # 值校验后仍保持 safe 污点
        url = self.base + "/" + path
        resp = requests.get(url, timeout=10)
        return resp.text
```

要点：
- `seal`：实例属性 `self.base` 不可被外部篡改（`admin.base = "http://evil"` 编译期拦截）
- `guard`：协议 + 字符白名单，破坏即运行时 GuardError（携带行列号）
- `safe`：校验后的外部数据保持 safe 污点；若误流入 eval/os 等汇点，编译期报错
- 危险子模块属性（`requests.os`、`operator.attrgetter`）编译期 E0064 + 运行时
  `_fly_sb_check_modattr` 双层拦截

## 名单一致性（防漂移测试）

- 编译期 taint 源点：`internal/checker/taint.go`（requests 系 API）
- 运行时白名单：`internal/runtime/fly_runtime.py` `_FLY_SB_ALLOWED_MODS`（含 requests）
- 锁定测试：`internal/compile/compile_test.go` `TestSandboxEscape`（allow_requests_s6）
  与 `TestThirdPartyWrapper`（示例通过检查 + 危险属性拦截 + 合法源点放行）

> 变更任一名单必须同步另一处并跑上述测试——编译期承认而运行时拒绝（或反之）都算回归。
