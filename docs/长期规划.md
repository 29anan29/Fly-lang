# Fly-Lang 长期规划：让语言自己成体系

> 状态：草案 / 待评审
> 配套文档：[../Plan.md](../Plan.md)（P0-P6 实现方案）、[Rust迁移方案.md](Rust迁移方案.md)（R0-R5）、[../方案.md](../方案.md)（语言设计）
> 阶段编号沿用既有体系：P（Go 实现）、R（Rust 迁移），本文档新增 L（Long-term，自洽自养自举）
> 生态立场：**寄生 Python**——Fly 是 Python 超集，包管理/依赖/生态直接复用 PyPI + pip/venv，不自建 registry、不搞自研标准库（`flyx` 无计划），这是既定立场而非待决策项

## 1. 愿景

Fly 不止是一门"能编译的 Python 安全超集"，而是一个**自洽、自养、自举**的体系：

- **自洽**：编译期检查、错误格式、发布渠道、编辑器支持，全部同一套契约，无历史包袱
- **自养**：每个环节（测试→CI→发布→升级→插件）全自动，维护者只需打 tag
- **自举**：语言工具链用这门语言自己编写——先用 Fly 写 fmt/doc/test，最终写编译器组件，双实现互证正确性

## 3. 成体系的三大支柱

### 3.1 自举（Self-Hosting）——核心

转译器存在"鸡生蛋"问题（Fly 写编译器需要先有编译器），务实路径是**分级自举**：

| 层级 | 内容 | 语言 | 意义 |
| :- | :--- | :--- | :--- |
| L1 工具自举 | fly fmt / fly doc / fly test | **Fly** | 工具链本体是 Fly 程序，自己跑在自己之上 |
| L2 后端自举 | 代码生成器（AST→Python 发射器）用 Fly 重写 | **Fly** | 编译器最"机械"的部分换皮验证 |
| L3 前端自举 | lexer/parser/checker 用 Fly 实现 | **Fly** | 完整参考实现；与 Rust 主实现双轨互证 |
| 引导链 | 自举版编译器的产物由 Rust 版 `fly build` 编译 | 混合 | 每次升级后自举版可自编译自己（`fly build flyc.fly` 产出 flyc.py 再编译 flyc.py） |

原则：
- **双实现互证**：Rust（主实现，性能/分发）+ Fly（参考实现，可读性/正确性），golden 输出逐字节对比是自举期的"裁判"
- 自举组件先做**可编译**（P0 子集 + 自带库），不做一次性大爆炸
- 自举版编译器不取代 Rust 版——Rust 版是分发物，Fly 版是体系自证

### 3.2 寄生 Python（生态即 PyPI）

不构建自己的生态，而是把 Python 生态直接当作自己的生态：

| 场景 | 立场 |
| :--- | :--- |
| 依赖管理 | 直接 pip/venv；Fly 不提供 `pkg` 子命令，不发明包格式 |
| 标准库 | 用 Python 标准库；runtime（`fly_runtime.py`）保持最小内置，只服务 8 关键字运行时需求 |
| 第三方库 | 生成的 .py 原样 import 任何 PyPI 包（寄生即兼容，安全关键字只约束 .fly 源码） |
| 示例库 | example/ 两个 FlyToDos（Web + PyQt6）即模板 |

### 3.3 质量（Quality）

| 层 | 手段 |
| :--- | :--- |
| 单测 | lexer/parser 节点级表驱动（已有） |
| golden | 全量输出快照对比（P6 补全）；自举期 Rust vs Fly 双实现 diff |
| 反例 | `# fly:error` 表驱动（已有框架，P1-P4 扩充） |
| fuzz | Go 原生 fuzz 测 lexer/parser 崩溃与挂起（R 版用 cargo-fuzz） |
| 行为 | 生成 .py 用 Python 3.10+ 实跑（CI 矩阵 linux/macos/windows） |
| 差分 | `scripts/diff_golden.sh`：Rust vs Fly 自举版输出逐字节比对 |

### 3.4 治理（Governance）

- **RFC 流程**：`docs/rfcs/`，任何语言语法/关键字/工具链改动先提 RFC（模板含动机/语义/反例/迁移）
- **版本策略**：SemVer + dev/release 双渠道（已实现）；`tools/release.sh` 一键发布（已实现）；CHANGELOG 从 conventional commits 自动生成
- **安全**：SECURITY.md（已有）+ 漏洞报告私信；`guard`/`mask`/`cage` 落地后做安全自检清单
- **社区**：CONTRIBUTING（已有）、good-first-issue 标签、示例/教程仓库
- **文档站**：GitHub Pages 或 docsify（D-4），README 自动同步

## 4. 阶段路线图

### L0 收尾与基线（当前 → v0.3.0）

**当前进度（2026-08，提交 aecd09e）**

- ✅ P1 lock/guard 完成：`internal/checker/`（symbol.go 作用域符号表 + lock.go 冻结常量拦截 + guard.go 条件验证 + 错误聚合上限 20 条）；parser 支持 `lock`（带值/裸标记）与 `guard`（带类型 `x: int, cond` / 纯条件 `x > 0`）语法；gen 展开 guard 为 `if not (...): raise GuardError(...)` 并注入 GuardError 类（docstring 后），lock 零运行时残留；LSP 诊断同管线同步
- ✅ P2 safe/mask 完成：`checker/taint.go` 污点引擎（顺序数据流 def-use 链：赋值/容器/属性/下标传播、清洗函数 int/float/bool、函数返回污点、f-string 变量提取）；源点（`input()`/`request.*`/`os.environ`）；汇点（`eval`/`exec`/`compile`/`os.system`/`subprocess.*`/`execute` SQL；`print`/`logging.*` 输出）；safe/mask 零运行时残留
- ✅ P3 only/seal/trace 完成：`checker/only.go`（onlyDeny 黑名单 30+ 危险名 + collectRefs 全语句收集 + seal 实例静态拦截 `admin.role = "x"` + trace 级别校验与 `_fly_` 保留前缀）；parser 新增 only/trace/seal 语法；gen 注入（only：`__builtins__` 替换为 `_FlyOnly` 白名单代理 + `_fly_patch_builtins` 函数包装；seal：类体注入 `__setattr__`/`__delattr__`（`_fly_seal_initializing` 门控，`__init__` 内允许赋值）；trace：函数包装为入口/出口 logging（args/ret 可选））；`internal/runtime/fly_runtime.py` go:embed 起步，按 `# fly:section:` 标记按需注入 guard/only/trace 三节
- ✅ 测试：golden（lock/guard/safe_mask/p3）+ 18 个 errors 反例 + checker 单测，`go test ./... && go vet ./...` 全绿；生成的 .py python3 实跑（guard 6 种拦截场景验证）验证通过；`方案.md` 示例 1/4/2/7/8 验收通过（only 内 os 报错、seal 实例赋值报错、trace 出入日志 + 运行时 seal 篡改抛 AttributeError）

剩余任务：

- 🔲 P4 cage + runtime 库：时间/内存资源约束
- 🔲 P6：golden 全量覆盖、错误消息快照、边界用例（闭包/嵌套/f-string 内 mask）
- 🔲 行为测试接入 CI（python3 实跑）
- 验收：`方案.md` 全部 8 个示例正反例通过；`go test ./... && go vet ./...` 全绿

### L1 Rust 迁移（→ v1.0.0）

- 按 [Rust迁移方案.md](Rust迁移方案.md) R0-R5 执行；R5 时打 v1.0.0 并退役 Go 版
- 迁移完成后 `fly` 为单静态二进制（<3MB），插件/CI/update 契约零改动
- 验收：golden 与 Go 版逐字节一致；v1.0.0 产物与 v0.2.1 同构

### L2 工具链（Fly 自写工具）

- `fly fmt`：AST 驱动格式化（注释保留）；**用 Fly 编写**，Rust 版通过 FFI 或子进程调用（D-2）
- `fly doc`：docstring → Markdown 文档生成器，**用 Fly 编写**
- `fly test`：目录级测试运行器（`fly test ./tests`），断言库内置
- 编辑器矩阵：Neovim（LSP 客户端配置）、JetBrains（LSP 通用协议）
- 验收：`fly fmt` 格式化自身源码后 golden 无差异（dogfooding 自证）

### L3 自举里程碑

- 编译器后端（gen 发射器）用 Fly 重写，golden 与 Rust 版 diff 全绿
- 前端（lexer/parser）用 Fly 实现 `flyc.fly`，自编译闭环：
  `fly build flyc.fly → flyc.py → python3 flyc.py（编译任意 .fly）`
- 验收：Fly 写的编译器能编译 FlyToDos 并产出可运行 .py

### L4 开放协作

- RFC 流程上线、CHANGELOG 自动生成、文档站部署、playground（Web 端 `fly lsp`/`CheckSource` 服务）
- 安全评审清单 + 漏洞披露流程
- 验收：外部贡献者提交 PR 全流程无维护者人工干预

## 5. 关键决策点

| # | 决策 | 建议（默认） | 备选 |
| :- | :--- | :--- | :--- |
| D-1 | 自举地位 | Fly 版编译器为**参考实现**（双实现互证），Rust 版保持分发物 | Fly 版替代 Rust 版（性能不达标，不推荐） |
| D-2 | 工具语言 | **用 Fly 写 fmt/doc/test**（自举优先），Rust 壳调用 | 全 Rust（快但放弃自举） |
| D-3 | 文档站 | GitHub Pages + docsify（零成本） | 自建（维护成本） |
| D-4 | 自举编译器运行形态 | 编译为 .py 由 python3 跑（无自举引导问题） | 编译为原生（需要自举引导，复杂） |

> 已定（非决策项）：包管理/标准库**寄生 Python**（pip/PyPI 直接复用，见 3.2）；无自研 registry、无 flyx 包。

## 6. 风险

| 风险 | 等级 | 缓解 |
| :--- | :--- | :--- |
| P1-P4 关键字语义落地拖延 | 高 | 每个关键字独立验收（Plan.md 已拆分）；文档示例即验收 |
| Rust 迁移与工具链建设并行冲突 | 中 | 阶段串行：L1 完成前不做 L2+（工具链在 Rust 版上建立） |
| 自举版漂移 | 中 | golden diff 脚本 + 双实现互证；自举版只做参考 |
| 单人维护精力 | 低 | 全自动 CI/发布已就绪；RFC 流程降低决策成本 |
